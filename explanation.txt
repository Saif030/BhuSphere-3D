# BhuSphere 3D - Comprehensive Project Explanation

## Project Overview

BhuSphere 3D is a full-stack 3D cadastral intelligence platform designed for SIH 2026 (Problem Statement 26011: 3D ULPIN Generation & Vertical Property Mapping). The project extends conventional 2D land parcel records into vertically structured property identities, enabling proper administration of multi-story buildings, basements, and underground infrastructure.

**Tagline**: "From 2D Land Parcels to 3D Property Intelligence"

## Core Problem Addressed

Current cadastral systems in India and globally are fundamentally 2D, representing land parcels as flat polygons. This creates several critical limitations:

1. **Vertical Property Rights**: Apartments, condos, and multi-story buildings cannot be accurately represented
2. **Taxation Inequity**: Property tax assessment lacks precision for different floor levels and building heights
3. **Dispute Resolution**: Land disputes arise from unclear vertical boundaries, especially for basements and overlapping structures
4. **Urban Planning**: Underground utility mapping is incomplete, leading to construction conflicts and service disruptions
5. **Data Integration**: Multiple data sources (GIS, LiDAR, surveys) exist but lack unified 3D reconciliation

## Solution Architecture

### High-Level Architecture
```
React (Vite+TS+Tailwind+MapLibre+Three.js) → FastAPI → SQLAlchemy → SQLite (demo) / PostGIS (prod)
Services: ULPIN engine · property · spatial queries · validation engine · AI copilot (safe tools) · audit
3D: procedural floor volumes + exploded view + underground tubes (swap for Cesium Ion + 3D Tiles in prod)
```

### Data Model

The system uses 13 core database tables:

1. **Parcel**: 2D land parcel boundaries with geometry
2. **Building**: Structures within parcels with height information
3. **Floor**: Individual floors with z-range (z_min, z_max) for 3D volumetric representation
4. **Unit**: Individual property units within floors
5. **Owner**: Property ownership information
6. **Right**: Property rights and interests
7. **Utility**: Underground infrastructure (water, electrical, telecom)
8. **DataSource**: Metadata for data sources (GIS, LiDAR, drone, etc.)
9. **PropertySource**: Links between properties and data sources
10. **ValidationIssue**: Automated validation results with severity and confidence
11. **PropertyHistory**: Temporal tracking of property changes (2024-2026)
12. **AuditLog**: Complete audit trail of all system actions
13. **Submissions**: Citizen-submitted property data (intake workflow)

Geometry is stored as GeoJSON JSON columns with center points and z_min/z_max for 3D volumes.

## Technical Implementation

### Backend (FastAPI + SQLAlchemy)

**Core Modules:**

- **database.py**: Database engine and session management with PostGIS-ready architecture
- **models.py**: SQLAlchemy ORM models for all 13 tables with GeoJSON geometry support
- **ulpin.py**: 3D ULPIN generation following pattern DL-{District}-{Local}-{Parcel}-{Building}-{Floor}-{Unit}
- **seed.py**: Deterministic synthetic data generator (random.seed(2026)) creating 14 parcels, 30 buildings, 378 floors, 2,529 units
- **validation.py**: 12 automated validation checks with severity scoring and confidence assessment
- **aicopilot.py**: Natural language query interface using deterministic rule-based analysis
- **main.py**: FastAPI application with 20+ REST endpoints and auto-generated API documentation

**Key API Endpoints:**

- Cadastre: `/api/parcels`, `/api/buildings`, `/api/floors`, `/api/units`, `/api/properties`
- ULPIN: `/api/ulpin/generate`
- Validation: `/api/validation/issues`, `/api/validation/run`, `/api/validation/{id}/review`
- AI/Search: `/api/ai/query`, `/api/search`
- Dashboard: `/api/dashboard/stats`
- Submissions: `/api/submissions` (CRUD + workflow)
- Data Import: `/api/data/import`, `/api/data/commit`

### Frontend (React + TypeScript)

**Core Components:**

- **Layout.tsx**: Navigation sidebar with role-based access control
- **Map2D.tsx**: MapLibre GL integration with parcel/building/utility layers
- **Building3D.tsx**: Three.js procedural 3D building visualization with exploded views
- **Copilot.tsx**: AI assistant panel with natural language interface
- **ConfidenceRing.tsx**: SVG donut chart showing verification confidence (95/80/60 thresholds)

**Pages:**

- **Dashboard.tsx**: KPI cards, severity charts, recent issues feed
- **Map.tsx**: 2D map with search, layer toggles, and detail drawers
- **Viewer3D.tsx**: 3D building viewer with floor selection, unit inspection, and tabs for Info/Evidence/History/QR/Report
- **Ops.tsx**: Validation center, infrastructure overview, admin tools
- **Property.tsx**: Public QR identity page with non-sensitive reference data
- **Submit Data**: Citizen submission wizard with 7-step workflow

## Key Features Explained

### 1. 3D ULPIN Generation

**Pattern**: DL-SKT-0182-B01-F08-U804
- DL: District code
- SKT: Locality (Saket)
- 0182: Parcel number
- B01: Building 1
- F08: Floor 8
- U804: Unit 804

Each ULPIN includes:
- Internal UUID for system reference
- Prototype 3D ULPIN (demo identifier, not official)
- Geometry hash for change detection
- Confidence status (95%+ verified, 80-95% likely, 60-80% needs review, <60% unverified)
- Disclaimer that these are demo identifiers

### 2. Validation Engine

**12 Automated Checks:**

1. Parcel overlap detection
2. Building-outside-parcel verification
3. Floor overlap analysis
4. Missing floor detection
5. Invalid z-range checks
6. Height mismatch (>2m threshold)
7. Unit-outside-floor structural validation
8. Duplicate ID detection
9. Utility crossing detection
10. Missing ownership checks
11. Self-intersection detection
12. GNSS data consistency notes

Each issue includes:
- Severity level (critical/high/medium/low)
- Evidence from multiple data sources
- AI confidence score
- Recommended action
- Current status (open/under review/resolved)

### 3. AI Copilot

**Deterministic Rule-Based Analysis:**

The AI copilot uses safe tool handlers (no raw SQL) to answer natural language queries:

- Height mismatch analysis
- Conflict detection between data sources
- Utility/parcel intersection queries
- Above-floor-N filtering
- Needs-verification identification
- Unit-specific explanations (e.g., "Why is A804 marked 96.4%?")
- Locality statistics
- ULPIN lookups
- Helpful fallback for unrecognized queries

**Architecture for LLM Integration:**

The system is designed to support future LangGraph + pgvector RAG integration over historical approval documents, with current rule-based handlers ensuring safety and reliability for demo purposes.

### 4. Citizen Submission Workflow

**7-Step Wizard:**

1. Property selection via map interface
2. Basic information entry
3. Measurements with automatic sq.ft to sq.m conversion
4. Ownership claim and documentation
5. Document upload (multipart to backend/uploads/)
6. Review and duplicate detection
7. Submission with tracking ID

**Officer Review Process:**

- Verification queue with filtering
- Side-by-side comparison with live records
- 2D/3D deep links to existing cadastre
- Decision workflow (approve/reject/request field verification)
- Field verification checklist integration
- Correction and resubmission support

**Audit Trail:**

Every submission action is logged with:
- User role and timestamp
- Decision and justification
- Field verification results
- Integration status (PENDING_VERIFICATION → AUTHORIZED → INTEGRATED/NEEDS_REVIEW)

### 5. 3D Visualization

**Procedural Generation (Demo):**

- Stacked translucent floor boxes from basement to roof
- Color-coded by verification status
- Exploded view for individual floor inspection
- Unit subdivision on selected floors
- Underground utility tube visualization
- Interactive OrbitControls for navigation

**Production Path:**

Designed to swap procedural generation for Cesium Ion + 3D Tiles for:
- Real city-scale 3D models
- Streaming performance for large datasets
- Integration with official 3D city data
- Photorealistic rendering

**Features:**

- Vertical floor list with labels (B2/B1/G/F01...) and z-range
- Unit grid with selection highlighting
- Underground mode toggle
- Evidence, History, QR, and Report tabs
- Print-friendly reporting

## Data Sources Integration

**Seven Data Sources:**

1. **GIS Cadastral Maps**: Official 2D parcel boundaries
2. **LiDAR Point Clouds**: 3D elevation and structure data
3. **Drone Imagery**: Aerial photography and photogrammetry
4. **GNSS Survey Data**: High-precision coordinate measurements
5. **Floor Plans**: Architectural building plans
6. **Digital Elevation Models (DEM)**: Terrain elevation data
7. **Property Registry**: Official ownership and transaction records

**Evidence Scoring:**

Each property unit receives evidence scores from each source, contributing to an overall confidence percentage. Discrepancies between sources trigger validation issues for officer review.

## Security and Audit

**Role-Based Access Control:**

- **Officer**: Full cadastre access, validation management, submission review
- **Surveyor**: Field data collection, verification, submission review
- **Admin**: System configuration, audit trail, data import
- **Citizen**: Submit property data, track submission status
- **Public**: Access public property identity pages via QR codes (non-sensitive data only)

**Audit Trail:**

Every system action is logged with:
- Timestamp and user identity
- Action type and affected entities
- Previous and new values
- IP address and session information

**Public Identity:**

QR code pages expose only reference data:
- Prototype 3D ULPIN (not official)
- Parcel/building/floor/unit identifiers
- Area and elevation information
- Confidence status
- No owner PII or sensitive information

## Limitations and Future Work

**Current Limitations:**

- Mobile 3D visualization is desktop-first
- Basemap requires internet connection (Carto Dark Matter)
- Demo endpoints (`/api/seed`, `/api/validation/run`) need protection for shared deployment
- Procedural 3D generation (to be replaced with Cesium 3D Tiles)
- OSM footprints don't align 1:1 with demo parcels

**Future Enhancements:**

- PDF report generation for official records
- Advanced ingestion parsers for various data formats
- Real-time data synchronization with official sources
- Mobile-optimized 3D visualization
- Offline capability for field operations
- Blockchain-based audit trail for enhanced security
- Machine learning models for automated validation

## Conclusion

BhuSphere 3D represents a comprehensive approach to modernizing cadastral systems for the vertical dimension of cities.
